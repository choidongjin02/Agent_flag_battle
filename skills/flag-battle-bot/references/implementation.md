# 봇 구현 계약

프로젝트의 `docs/IMPLEMENTATION_CONTRACT.md`에 모듈 경계와 완료 기준이 있다. 다음을 유지한다.

- SDK 입력은 INIT와 각 TURN 별 END 블록이다. 매 턴 UNITS는 전체 snapshot. 프로세스는 EOF까지 반복한다.
- `main.py`에서 제공 `protocol.run(decide)`를 사용하면 END/flush를 중복 구현하지 않는다. 런타임 상태의 예외 처리 정책은 별도로 검증한다.
- 신규 생산 병력까지 포함한 가상 출발 풀로 계획한다. 입력에 있던 그룹만 순회하면 신규 생산지의 인원을 당일 움직이지 못한다.
- 생산 계획을 먼저 확정하고 이동을 예약하는 2단계 builder를 사용한다. 임의 호출 순서를 엔진과 동일하게 지원한다고 주장하지 않는다.
- 이동 원천 잔여/도착분을 분리하고 합법 분할 이동의 합계를 검사한다. 부분 이동·부분 생산은 공식 동작이며 그 자체가 오류는 아니다.
- 위협 계산은 적 W 대기/이동, 합법적인 생산 배분, TELE를 포함한다. 본진·모든 병원에서 상대 전체 예산을 각각 더하면 같은 셀의 위협도 과대평가할 수 있다.
- F 생존에는 W≥적W, 상대 비전투 유닛 제거에는 W≥적W+1. 호위와 공격의 필요 수량을 구별한다.
- 점령 예산 `min(40,R−생산비+전투후수입)`과 우선순위를 함께 결정한다. 최종 턴에도 적용한다.
- 중앙/지역 구분은 제공 config의 x 구간(0~4 / 5~9 / 10~14)을 사용한다. 특히 STATION을 본진 거리 차로 분류하지 않는다.
- 대칭 점수는 pair별로 하나의 숨은 변수로 취급한다. 추론 값과 공개 플래그를 구분한다.
- 좌표·방향 동률 결정에도 180도 정규화를 적용해 회전 테스트한다. 단순히 BFS만 쓴다고 진영 대칭이 보장되지 않는다.
- `PRIORITY`는 점령 배정에 의미가 있을 때 생성한다. 항상 출력해야 한다는 규칙은 없다.
- 의존성은 제공 환경에 맞춘다. import 이름만 검사해서 서버 실행 가능 여부를 단정하지 않는다.

시간 측정은 입력 전송부터다. `decide` 시작 시각은 서버 deadline의 시작이 아니다. 로컬 100ms 또는 탐색 150ms 중단은 가능한 초기 여유 설정일 뿐, 서버 안전 보장이 아니다. 초기 3초도 import·초기화·첫 응답을 포함한다.
