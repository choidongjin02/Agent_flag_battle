# 깃발 대항전 규칙 판정

먼저 작업 폴더 또는 상위 폴더에서 `flag-battle.project.json`을 찾는다. 없으면 사용자가 지정한 프로젝트를 확인한다. 경로가 없는 경우 필요한 SDK 위치를 묻고, 임의로 자체 맵·엔진을 만들지 않는다. 프로젝트를 옮겼다면 절대 경로를 이전 채팅에서 가져오지 않는다.

## 근거 선택

- 프로젝트의 `vendor/development/docs/rulebook.md`, `config/balance.json`, `bots/dist/starter/limits.json`이 제공 자료다. 엔진은 `engine/pipeline.py`, 입력·명령 파서는 `runner/protocol.py`이다.
- 프로젝트가 없는 규칙 질의에는 [배포 규칙 사본](references/provided-rulebook.md)을 사용할 수 있다. 실행 환경과 SDK 버전 확인은 [근거 지도](references/source-map.md)를 읽는다.
- 최신 대회 공지/사용자가 제공한 공식 정정이 기존 SDK와 다르면 둘을 구분해 보고한다. 자체 해석이나 과거 스킬을 공식 근거보다 우선하지 않는다. 런타임 한계는 플랫폼 문서를 함께 확인한다.

## 판정

관측·양측 명령·필요한 과거 이력을 분리하고, 결과에 영향을 주는 단계만 따라간다: 생산 → 동시 이동 → 전투 → 효과/수입 → 점령 → 보급소 후지급·누적 점수 → 공개 → 승리. 복잡한 전이만 중간 상태를 보여준다.

- 생산된 인원은 당일 이동 가능. 도착분은 원래 위치의 이동 가능 풀에 다시 넣지 않는다.
- F 생존에는 W 동수로 충분하지만 상대 F/S 제거에는 W 1명 우세가 필요하다. 동수+양측 F는 경합이다.
- 수비 F 전멸은 즉시 중립화; 공격 F가 생존하면 당일 점령 가능. 빈 건물과 구분한다.
- 생산은 수입 전 자원, 점령은 수입 후 자원. LIBRARY는 점령 단계 진입 시 고정, DEPOT는 모든 점령 후 지급한다.
- 점수 최종합 → 누적 점령-턴 → 생존 병력 순이다. 누적 점수·경제 휴리스틱을 최종 승패 판정으로 쓰지 않는다.
- `N 1`은 누가 중립화했는지 알려주지 않는다. 대칭 추론과 엔진의 팀별 점수 공개 플래그도 구별한다.

구체적인 함정은 [검증된 경계 사례](references/edge-cases.md)를 필요할 때 읽는다. SDK로 확인된 동작을 다시 “미확정”으로 분류하지 않는다. 시나리오 실행이 필요하면 프로젝트의 `tests/test_rules.py` 패턴과 **제공 `run_turn`**을 사용한다. 단위 검증은 승률 측정이 아니다.

결과에는 근거 함수나 규칙 절을 붙이고, 가정·제공 SDK 관찰·전략적 추론을 구분한다. 외부 문의 전송은 이 스킬이 허가하지 않는다.
